# OpenTravel Alliance

> Volunteer, non-profit travel technology standards body (Melbourne, Florida, founded 1999).
> Publishes the OpenTravel Specification — the OTA 1.0 XML message suite (releases 2001A
> through 2024A) and the model-driven OpenTravel 2.0 Object Model (OTM), which compiles to
> XML Schema, JSON Schema and Swagger 2.0 resource contracts — plus the OpenTravel Code Lists
> used across air, hospitality, car rental, cruise, rail, GDS, channel and technology-provider
> systems. Specifications are royalty-free and free of charge.

Generated by API Evangelist on 2026-07-28 because opentravel.org publishes no /llms.txt
(HTTP 404). Facts below are drawn from apis.yml and the artifacts in this repository.

## What OpenTravel is not

- It operates **no runtime API**. Every Swagger 2.0 document it publishes declares a
  placeholder host (`127.0.0.1` or `example.com`) and is a contract for an implementer to
  host, not an endpoint OpenTravel serves.
- There is **no certification programme**, no conformance test suite and no certified
  implementer registry. The adopter list is self-nominated.
- There is **no status page**, no SLA, no deprecation policy and no dated changelog.

## Machine-readable contracts in this repository

- `openapi/opentravel-2020a-hotel-descriptive-content-resource-openapi.json` — Swagger 2.0,
  operations `Get`, `Query`, `Notification`.
- `openapi/opentravel-2020a-facility-resource-openapi.json` — Swagger 2.0, operations `Post`, `Get`.
- `openapi/opentravel-2018a-hospitality-offers-resource-openapi.json` — Swagger 2.0, operations
  `FindSinglePropertyOffers`, `FindMultiPropertyOffers`.
- `openapi/opentravel-2018a-facility-resource-openapi.json` — Swagger 2.0, operations
  `FindHospitalityAvailability`, `RetrieveHospitalityAvailability`, `HospitalityFacilitySearch`.
- Each has a `-defs-` sibling carrying the inlined model definitions (337, 232, 372 and 187
  definitions respectively).
- `json-schema/` — the seven OTM `_Trim` JSON Schema draft-04 modules those contracts `$ref`
  (163 definitions): Common 5.0.0, Organization 4.1.0, OrganizationHospitality 4.0.0,
  FacilityResource 1.0.0, HospitalityContent 1.0.0, HospitalityFacility 1.0.0,
  HospitalityOffers 1.0.0 — plus the three `CodeList` libraries (4.0.0 and 4.1.0 from 2020A,
  3.0.0 from 2018A).
- `vocabulary/opentravel-alliance-vocabulary.yml` — the OpenTravel Code Lists read out of those
  CodeList modules: 193 code lists, 4,052 enumerated terms (bed types, booking channels,
  distribution types, meeting-room formats, cuisine types…). The canonical download at
  opentravel.org is an Excel workbook behind a lead-capture form; the JSON Schema form in the
  public mirror is the only ungated machine-readable copy.
- `examples/` — OpenTravel's own compiler-generated JSON example payloads for the 2018A
  hospitality resources, each bound 1:1 to a real `operationId` request or 201 response. No
  example payloads are published for the 2020A suite.
- `cli/opentravel-alliance-cli.yml` — `ota2compile`, the OTA2 Type Library Compiler CLI that
  produces every artifact above from an OTM library (`-S` Swagger, `-J` JSON Schema, `-E`
  examples, `-H` HTML docs, `-O` OpenAPI 3.x — the last never used for a published suite).

## Agent surfaces

- MCP server: `https://opentravel.org/wp-json/mcp/mcp-oauth-server` (OAuth 2.1 + PKCE, scope
  `mcp`). Auth-gated: an anonymous `tools/list` returns 401, so the tool set is not public.
  See `mcp/opentravel-alliance-mcp.yml`.
- OAuth metadata: `/.well-known/oauth-authorization-server` (RFC 8414) and
  `/.well-known/oauth-protected-resource` (RFC 9728). Both 200.
- This MCP surface belongs to the opentravel.org WordPress site. There is no evidence it
  exposes the specification corpus.
